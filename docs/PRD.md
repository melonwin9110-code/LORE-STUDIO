# LORE STUDIO — MASTER PROMPT ДЛЯ CODEX

## 1. Твоя роль

Ты — ведущий full-stack разработчик, системный архитектор и инженер по тестированию.

Твоя задача — разработать с нуля веб-приложение **Lore Studio**, предназначенное для создания, редактирования, хранения и публикации вымышленных вселенных.

Это не обычный текстовый редактор и не простой генератор персонажей. Lore Studio должна представлять собой связанную систему управления лором: персонажи, государства, географические карты, исторические события, отношения, семейные древа, энциклопедия и параллельные временные линии.

**Главные требования:**
- Реально работающий функционал, а не декоративные макеты.
- Чистая модульная архитектура.
- Возможность дальнейшего расширения без переписывания всего приложения.
- Русскоязычный интерфейс.
- Современный адаптивный дизайн с тёмной и светлой темами.
- Корректная работа нескольких пользователей.
- Сохранность данных.
- Автоматические и ручные тесты.
- Никаких обязательных платных API для запуска локальной версии.

Работай поэтапно. Не пытайся реализовать весь проект за один проход ценой неработающего кода.

## 2. Технологический стек

Предпочтительный стек:

- Frontend: Next.js, React, TypeScript.
- Стили: Tailwind CSS.
- UI: единая система переиспользуемых компонентов.
- Backend: серверные API на TypeScript.
- База данных: PostgreSQL.
- Геометрия: PostGIS.
- Карты: OpenLayers.
- Графы и схемы: React Flow.
- Текстовый Wiki-редактор: Tiptap.
- Совместное редактирование текста: Yjs и Hocuspocus на соответствующем этапе.
- Unit-тестирование: Vitest.
- E2E-тестирование: Playwright.
- Локальная инфраструктура: Docker Compose.

Можно выбирать дополнительные библиотеки, если они упрощают реализацию. Все существенные решения фиксируй в документации.

Используй актуальные совместимые стабильные версии зависимостей. Не выдумывай API библиотек.

- Биография.

- Способности и навыки.

- Исторические события.

Реализовать гибридную систему характеристик.

Поддерживаемые типы полей: текст, число, переключатель, список, множественный выбор, дата, ссылка на объект, изображение и вычисляемое значение.

Предусмотреть отдельный модуль процедурной генерации карт с параметрами:

Предусмотреть возможность частичной генерации отдельных слоёв и регионов без уничтожения остальных данных.

### Импорт карт

## 9. Историческая карта

Карта должна изменяться во времени.

Пример:

1000 год — существует единая империя.

1162 год — империя распалась.

1200 год — границы новых государств изменились.

При выборе 1000 года пользователь должен видеть исходную империю, а не её позднейшие границы.

Реализовать исторические версии геометрии и свойств объектов.

Поддержать изменение береговых линий, рек, государственных границ, городов и других элементов в выбранной временной точке.

Исторические изменения карты должны связываться с событиями хронологии.

## 20. Требования к тестированию

После каждого этапа:

1. Проверять TypeScript.
2. Запускать линтер.
3. Запускать unit-тесты.
4. Проверять API и базу данных.
5. Запускать интеграционные тесты.
6. Запускать E2E-тесты Playwright.
7. Проверять создание, редактирование и удаление объектов.
8. Проверять сохранение после перезагрузки страницы.
9. Проверять разрешения пользователей.
10. Проверять, что новые изменения не ломают существующий функционал.

Обязательные сценарии для расширенных этапов:

- Создание персонажа и связанных событий.
- Автоматическое обновление семейного древа.
- Изменение отношения во времени.
- Создание альтернативной ветки.
- Изменение персонажа только в одной ветке.
- Изменение политической карты только в выбранной линии.
- Экспорт и повторный импорт данных без потери связей.
- Защита приватного проекта от другого пользователя.
- Корректная обработка недоступного ИИ.

Тесты должны проверять реальное поведение приложения, а не только наличие компонентов.

Не используй фиктивные успешные тесты.

Если тест не удалось выполнить, явно укажи причину.

## 22. Правила работы Codex

Работай последовательно.

Не генерируй огромные объёмы кода без проверки работоспособности.

Не оставляй неиспользуемые компоненты и временные заглушки, выдаваемые за готовые функции.
