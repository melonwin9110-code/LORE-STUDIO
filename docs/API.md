# API Lore Studio — этапы 0–2

Автор проекта: **ElpisHeart**. Базовый путь: `/api`. Тело запроса и ответа — JSON. Запросы с телом используют `Content-Type: application/json`. Аутентификация выполняется cookie `lore_session`; пароль и токен сессии не возвращаются в JSON.

## Сессия

| Метод и путь | Запрос | Ответ |
| --- | --- | --- |
| `GET /session` | Нет | `{ "user": null }` или `{ "user": { "id", "name", "email" } }`. |
| `POST /auth/register` | `{ "name", "email", "password" }` | 201, `{ "user": ... }` и сессионная cookie. |
| `POST /auth/login` | `{ "email", "password" }` | 200, `{ "user": ... }` и новая сессионная cookie. |
| `POST /auth/logout` | Нет | `{ "ok": true }`, отзыв текущей сессии и очистка cookie. |
| `GET /health` | Нет | `{ "status": "ok", "database": "connected" }` после обращения к PostgreSQL и проверки миграций. Дополнительный `testDatabase` сообщает, оканчивается ли имя фактической БД на `_test`; тестовые запуски требуют `true`. |

Имя пользователя — от 1 до 80 символов после обрезки пробелов. Email валидируется и приводится к нижнему регистру, максимум 254 символа. Пароль — от 10 до 128 символов. Повторная регистрация email возвращает 409; неверный вход — 401. Ограничитель входа допускает до 10 попыток в 15-минутном окне для одного email; дальнейшие попытки возвращают 429.

Сессия действует 7 дней. Cookie имеет `HttpOnly`, `SameSite=Lax`, путь `/`; при `SECURE_COOKIES=true` — также `Secure`. Для изменяющего запроса передавайте корректный same-origin `Origin`. Клиент браузера делает это автоматически. За reverse proxy `APP_URL` задаёт ожидаемый внешний origin; без него используется origin запроса к Next.js.

## Проекты и миры

| Метод и путь | Запрос | Ответ |
| --- | --- | --- |
| `GET /projects` | Нет | `{ "projects": [...] }`, только доступные текущему пользователю. |
| `POST /projects` | `{ "name", "description"? }` | 201, `{ "project": ... }`. Проект приватный. |
| `POST /projects/demo` | Нет | `{ "project": ... }`. Создаёт приватную «Элирию» с миром, персонажами, отношениями и событиями; повторное обращение возвращает тот же демопроект. |
| `PATCH /projects/:id` | `{ "name"?, "description"? }` | `{ "project": ... }`. |
| `DELETE /projects/:id` | Нет | `{ "ok": true }`. Каскадно удаляет миры и лор. |
| `GET /projects/:id/worlds` | Нет | `{ "worlds": [...] }`. |
| `POST /projects/:id/worlds` | `{ "name", "description"? }` | 201, `{ "world": ... }`. |
| `GET /worlds/:id` | Исторический контекст в query | `{ "world", "characters": [...], "events": [...], "relations": [...], "history": ... }`. |
| `PATCH /worlds/:id` | `{ "name"?, "description"? }` | `{ "world": ... }`. |
| `DELETE /worlds/:id` | Нет | `{ "ok": true }`. Каскадно удаляет содержимое мира. |

Название — от 1 до 160 символов после обрезки пробелов; описание проекта или мира — до 10 000 символов. Все идентификаторы — UUID. Объекты другого пользователя возвращают 404, чтобы не раскрывать существование приватных данных.

## Персонажи

`POST /worlds/:worldId/characters` создаёт персонажа и возвращает 201 `{ "character": ... }`.

Обязательное поле — `name`. Дополнительные текстовые поля: `title`, `species`, `gender`, `appearance`, `personality`, `biography`, `motivation`, `abilities`, `secrets`. Годы `birthYear` и `deathYear` принимают целое число или `null`. `status`: `draft` по умолчанию либо `canon`. Год смерти не может быть раньше года рождения.

Пример:

```json
{
  "name": "Аэлин",
  "title": "Хранительница Белой башни",
  "species": "Человек",
  "birthYear": -120,
  "biography": "Исследует древние хроники Элирии.",
  "status": "canon"
}
```

`PATCH /characters/:id` принимает изменённые поля и обязательный актуальный `version`. Пропущенные поля не очищаются. Ответ — `{ "character": ... }` с увеличенным `version`.

```json
{ "biography": "Исправленная биография.", "version": 1 }
```

`DELETE /characters/:id` создаёт логическое удаление в выбранной линии и дате, корректирует отношения и участие в событиях той же линии. События сохраняются. Более ранние состояния и другие линии не удаляются.

## События

`POST /worlds/:worldId/events` → 201 `{ "event": ... }`. Поля:

- `name` и целый `startYear` — обязательны.
- `type` — текст до 160 символов, по умолчанию «Событие».
- `endYear` — необязательный год или `null`, не раньше начала.
- `description` — текст.
- `characterIds` — до 500 неповторяющихся UUID персонажей этого мира, по умолчанию пустой массив.
- `status` — `draft` или `canon`.

`PATCH /events/:id` принимает изменённые поля и актуальный `version`; ответ `{ "event": ... }`. `DELETE /events/:id` создаёт логическое удаление события в выбранной линии и дате, сохраняя персонажей и прежние исторические состояния.

## Отношения

`POST /worlds/:worldId/relations` → 201 `{ "relation": ... }`. Обязательные поля: `fromId`, `toId`, `kind`. Персонажи должны быть разными и принадлежать одному миру. `kind` — непустой текст до 100 символов. `mutual` — логический признак взаимности, по умолчанию `true`. `startYear` и `endYear` — необязательные целые годы или `null`; `description` — текст.

`familyKind` уточняет семейный смысл: `other` (по умолчанию), `parent`, `adoptive_parent` или `spouse`. Для родителя направление — `fromId` родитель → `toId` ребёнок. Сервер проверяет циклы происхождения и известные биологические противоречия. Братья и сёстры выводятся из родителей, отдельные записи для них не требуются.

`PATCH /relations/:id` принимает изменённые поля и актуальный `version`; ответ `{ "relation": ... }`. `DELETE /relations/:id` создаёт логическое удаление отношения в выбранной линии и дате.

## Исторический контекст

Для `GET /worlds/:id`, создания сущностей и `PATCH`/`DELETE` персонажей, событий и отношений доступны query-параметры:

| Параметр | Значение |
| --- | --- |
| `timeline` | UUID линии этого мира. При отсутствии выбирается основная линия. |
| `day` | Целый порядковый день десятичной строкой. День 0 — григорианский год 0, 1 января. При отсутствии читается последнее состояние. |
| `revision` | Необязательный зафиксированный срез редакций, только для чтения. Передача в изменяющий запрос запрещена. |

Пример: `GET /worlds/:worldId?timeline=:timelineId&day=0`.

Без исторических параметров прежние маршруты остаются совместимыми с первым выпуском. Новая карточка получает исходный день, а изменение последнего состояния сохраняется с датой его действия. Для явной исторической правки передавайте `day`. Редактирование дочерней линии раньше её `forkDay` отклоняется.

`history` ответа мира содержит:

```text
{
  timeline: Timeline,
  timelines: Timeline[],
  calendars: CalendarRecord[],
  day: string | null
}
```

`Timeline`: `id`, `worldId`, `name`, `parentId|null`, `parentRevision|null`, `forkDay|null`, `headRevision`, `isMain`, `isCanon`. Номера редакций и дни — строки, признаки — boolean. `day=null` означает последнее состояние. Годы рождения, событий и интервалов отношений остаются григорианскими; выбор календаря исторического среза не переопределяет их.

## Временные линии

| Метод и путь | Запрос | Ответ |
| --- | --- | --- |
| `GET /worlds/:id/timelines` | Нет | `{ "timelines": [...] }`. |
| `POST /worlds/:id/timelines` | `{ "name", "isCanon"?, "parentId"?, "forkDay"?, "expectedParentRevision"? }` | 201, `{ "timeline": ... }`. |
| `PATCH /timelines/:id` | `{ "name"?, "isCanon"? }` | `{ "timeline": ... }`. |

При указанном `parentId` обязательны дата ответвления и ожидаемая актуальная редакция родителя. Ветка фиксирует оба значения. Устаревшая редакция даёт 409. Без `parentId` создаётся независимая пустая линия. UUID родителя должен принадлежать тому же миру и быть доступен пользователю. Основная линия создаётся автоматически; API удаления линий в текущий этап не входит.

## Сравнение и перенос

`GET /timelines/:id/compare?other=:otherId&day=:day` возвращает `{ "differences": [...], "leftRevision": "123", "rightRevision": "456" }`. `day` необязателен. Каждый элемент содержит `id`, `kind` (`characters/events/relations`), `change` (`added/removed/changed`), `left` и `right` (содержимое либо null). Слева — линия из пути, справа — `other`. Служебные `version`, `id`, `worldId` не считаются содержательным различием. Редакции соответствуют показанным состояниям и позволяют проверить обе стороны перед переносом. Сравниваются линии одного мира с проверкой доступа.

`POST /timelines/:targetId/transfer`:

```json
{
  "sourceId": "UUID исходной линии",
  "objectIds": ["UUID объекта"],
  "sourceDay": "0",
  "targetDay": "0",
  "expectedRevision": "123",
  "expectedSourceRevision": "456",
  "overwrite": false,
  "includeDependencies": true
}
```

`sourceDay` и `targetDay` необязательны; `expectedRevision` — актуальный head цели, не версия отдельной карточки. Необязательный `expectedSourceRevision` проверяет head источника. Интерфейс передаёт обе редакции из сравнения; изменение любой стороны возвращает 409 до записи и требует обновить сравнение. По умолчанию отличающееся существующее содержимое не перезаписывается. Для согласованной пользователем замены явно передайте `overwrite=true`. `includeDependencies=true` включает необходимых связанных персонажей; иначе отсутствующие ссылки отклоняются. Проверяются мир, доступ, ссылки и семейные ограничения. Операция атомарна, сохраняет UUID и не изменяет источник. Ответ: `{ "ok": true, "transferred": число }`.

## Календари

`GET /worlds/:id/calendars` → `{ "calendars": [...] }`.

`POST /worlds/:id/calendars` принимает `{ "definition": ... }`, возвращает 201 `{ "calendar": ... }`. Запись содержит `id`, `worldId`, `definition`, `isDefault`. Определения неизменяемы: API их изменения и удаления не предоставляется.

Пример определения:

```json
{
  "name": "Календарь двух лун",
  "months": [{ "name": "Рассвет", "days": 30 }, { "name": "Долгая ночь", "days": 40 }],
  "leap": { "every": 5, "exceptEvery": null, "includeEvery": null, "month": 2, "days": 1, "offset": 0 },
  "epochOffset": "0",
  "era": "эры Элирии"
}
```

Месяцы нумеруются с 1. `leap=null` отключает дополнительные дни. `epochOffset` — общий порядковый день начала года 0 календаря; `era` — подпись, а не исполняемая формула. Стандартный календарь использует григорианское правило 4/100/400. Конвертация выполняется чистыми функциями `toOrdinal`/`fromOrdinal` без отдельного внешнего API, в том числе для отрицательных лет. Невалидные определения и даты отклоняются.

## История редакций объекта

`GET /characters/:id/history?timeline=:timelineId`, а также аналогичные пути для `events` и `relations`, возвращают:

```text
{ revisions: [{ revision, timelineId, effectiveDay, version, deleted, data, createdAt }] }
```

`revision` и `effectiveDay` — строки, `deleted` — boolean, `data` — содержимое либо null, `createdAt` — служебный timestamp. Чтение учитывает закреплённые редакции предков линии и её дату ответвления. Чужие и неунаследованные будущие редакции родителя не раскрываются. Этот маршрут показывает историю; он не является командой автоматического слияния или произвольного изменения старого payload.

## Общие правила

Исторические годы — целые числа от −1 000 000 000 до 1 000 000 000. Даты лора не преобразуются в `JavaScript Date`. Короткие строковые поля ограничены 160 символами, длинные тексты сущностей — 40 000. Неизвестные поля отклоняются, служебные UUID и `worldId` нельзя подменить в теле запроса. Максимальный размер тела — 256 КиБ.

Стандартная ошибка: `{ "error": "Понятное сообщение" }`.

| Код | Значение |
| --- | --- |
| 400 | Неверные поля, JSON, годы или ссылки на персонажей. |
| 401 | Требуется вход или неверные данные авторизации. |
| 403 | Запрещённый источник запроса или недостаточная роль участника. |
| 404 | Объект не существует, UUID в пути некорректен или объект недоступен текущему пользователю. |
| 409 | Email занят, устарела версия/редакция, найден конфликт переноса или связанного состояния. |
| 413 | Тело запроса превышает лимит. |
| 415 | Ожидается `application/json`. |
| 429 | Превышено число попыток входа. |
| 500 | Внутренняя ошибка; подробности не предназначены для клиента. |
| 503 | PostgreSQL недоступен или миграции не применены. |

При 409 сохраните локальный текст, перечитайте мир и сравните изменения. Не выполняйте автоматическую перезапись свежей версии. DELETE сущности не требует версии, но использует выбранную линию и дату: удаление является явным подтверждённым действием пользователя.

Публичного API публикации, архивного экспорта/импорта, ИИ, приглашений и слияния временных линий в текущем выпуске нет.
