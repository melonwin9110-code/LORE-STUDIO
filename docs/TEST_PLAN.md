# План тестирования

Автор проекта: **ElpisHeart**. Текущий план относится к доработке географического этапа 3 в версии 0.5.0 и регрессии исторической системы и согласованных возможностей 0.3.0. Он описывает проверки; результаты конкретного прогона приводятся отдельно в отчёте задачи.

## Подготовка

Используйте отдельную локальную базу `lore_studio_test` для автоматических тестов, доступную приложению через `DATABASE_URL`. Интеграционные тесты создают уникальные аккаунты и проекты, затем удаляют созданные проекты; аккаунты могут остаться в тестовой базе. Браузерные проверки тоже создают данные. Не запускайте их против ценной рабочей базы.

```sh
npm ci
test -f .env || cp .env.example .env
docker compose up -d --wait db
npm run db:migrate
npm run test:prepare
```

`test:prepare` создаёт `lore_studio_test`, если она отсутствует, и применяет миграции. Команда не сбрасывает существующую базу и не удаляет данные. Для другого подключения задайте `TEST_DATABASE_URL`; имя базы должно оканчиваться на `_test`. Тот же URL передайте как `DATABASE_URL` тестовому серверу.

## Автоматические проверки

| Проверка | Команда | Что подтверждает |
| --- | --- | --- |
| TypeScript | `npm run typecheck` | Согласованность типов фронтенда, сервера и тестов. |
| ESLint | `npm run lint` | Статические правила и корректность использования React. |
| Unit | `npm test` | Валидацию, функции безопасности, календари с BigInt, правила семейного графа и входные данные геометрии. |
| Сборка | `npm run build` | Подготовку production-приложения. |
| Интеграционные | `npm run test:integration` | Настоящий API с PostgreSQL, операции лора, права и конфликты. |
| Браузерные | `npm run test:e2e` | Пользовательский сценарий в Chromium и сохранение после обновления страницы. |

Интеграционные тесты ожидают уже запущенный сервер. Запустите отдельный экземпляр на порту 3001 с тестовой базой:

```sh
DATABASE_URL=postgresql://lore:lore_local@127.0.0.1:5432/lore_studio_test npm run dev -- --port 3001
```

В другом терминале:

```sh
TEST_BASE_URL=http://127.0.0.1:3001 npm run test:integration
```

Playwright по умолчанию запускает сервер на порту 3001 с отдельной тестовой БД и ожидает `/api/health`. Если подходящий сервер уже запущен, он может переиспользоваться; явно заданный `TEST_BASE_URL` выбирает адрес сервера. Перед выполнением сценариев общий setup проверяет `testDatabase=true` в ответе фактического сервера. Интеграционные тесты имеют такую же предварительную проверку. Задавайте отдельную БД через `TEST_DATABASE_URL` и передавайте тот же URL как `DATABASE_URL` тестовому серверу. Имя должно оканчиваться на `_test`; одна только строка переменной не заменяет проверку реально обслуживающего запросы сервера.

Установка браузера и прогон:

```sh
npx playwright install --with-deps chromium
DATABASE_URL=postgresql://lore:lore_local@127.0.0.1:5432/lore_studio_test npm run test:e2e
```

Для установленного системного Chromium:

```sh
DATABASE_URL=postgresql://lore:lore_local@127.0.0.1:5432/lore_studio_test CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

`TEST_BASE_URL` позволяет выбрать сервер; он должен соответствовать проверяемому приложению. Playwright сохраняет трассировку и снимки при сбоях. Эти файлы могут содержать тестовые данные и не добавляются в Git.

## Обязательные сценарии API

- Регистрация, повторный email, корректный и неверный вход, состояние сессии, выход и невозможность повторного использования отозванной cookie.
- HttpOnly и SameSite cookie, запрет мутации с посторонним Origin, отсутствие пароля в JSON-ответах.
- Создание приватного проекта и мира, изменение названий, получение данных и удаление.
- Создание демонстрации «Элирия», наличие связанных объектов, идемпотентность повторного запроса и приватность демонстрации.
- Создание и изменение персонажа, сохранение биографии после нового чтения и нового входа.
- Создание события с участниками и отрицательным годом, обновление и удаление.
- Создание взаимного или направленного отношения, изменение описания и удаление.
- Отклонение дробного года, конца раньше начала, самоссылки отношения, повторных участников и UUID чужого мира.
- Скрытие чужих проектов, запрет прямого чтения, изменения и удаления чужих объектов.
- HTTP 409 при устаревшей версии персонажа, события и отношения без потери сохранённой правки.
- Каскадное удаление связей при удалении персонажа с сохранением несвязанных данных.

## Ручная проверка интерфейса

1. Откройте приложение, убедитесь, что видны название Lore Studio и автор ElpisHeart. Переключите светлую и тёмную темы.
2. Зарегистрируйтесь с уникальным email и паролем не короче 10 символов. Выйдите и проверьте повторный вход.
3. Создайте «Элирию» через действие демонстрационного проекта. Убедитесь, что присутствуют несколько персонажей, отношения и события.
4. Создайте новый проект и мир. Переключитесь обратно в демонстрационный мир и убедитесь, что данные не смешиваются.
5. Создайте персонажа, заполнив имя, вид и биографию. Измените биографию, сохраните и перезагрузите страницу.
6. Добавьте событие с годом и одним или несколькими персонажами. Проверьте порядок событий в хронологии. Исправьте описание и перечитайте страницу.
7. Создайте отношение между двумя персонажами. Проверьте направление, взаимность и сохранение.
8. Используйте поиск и мобильную ширину окна. Формы должны оставаться доступными, а поля — иметь понятные подписи.
9. На тестовых данных проверьте отмену и подтверждение удаления персонажа, события, отношения, мира и проекта.
10. Откройте приложение в отдельном профиле браузера с другим пользователем. Приватные проекты первого пользователя недоступны.
11. Сохраните правку из одной вкладки, затем попробуйте сохранить устаревший объект из другой. Должно появиться сообщение о конфликте без тихой перезаписи.
12. Перезапустите только приложение, затем контейнер PostgreSQL без удаления volume. После входа сохранённые объекты должны оставаться доступны.

## Проверки версии 0.5.0 — оформление, слои и готовая основа

Это план покрытия дополнений 0.5.0. Итоговые числа и команды должны появиться в отдельном датированном отчёте после завершения прогонов; результаты прежних выпусков ниже сохраняют исходный смысл.

- **Реальное оформление:** выделить точку, линию и территорию, менять заливку, контур и толщину без дополнительного применения; проверить сами пиксели полотна при активном выделении. Рамка не должна подменять стиль или поднимать географию над другими слоями. Для линии меняется цвет контура; внутренней заливки у неё нет.
- **Черновик:** проверить отмену/повтор цвета, толщины, подписи, имени и описания, затем явное сохранение и повторное чтение. Значения инспектора должны соответствовать состоянию черновика после отмены; изменение цвета не должно сбрасывать фокус всей формы.
- **Слои:** на реальном полотне скрыть/показать слой, изменить непрозрачность и порядок, заблокировать и разблокировать, перенести объект в другой слой. Глазок учитывает режим, показ политического слоя включает политическое представление. Скрытые и заблокированные объекты нельзя случайно передвинуть или изменить. Выбранный вручную рабочий слой не сбрасывается при смене типа рисуемого объекта.
- **Два начала:** через форму создать пустую карту и готовую основу каждого доступного варианта. Пустая карта не содержит автоматически созданных объектов. Новая основа не заменяет прежние карты, сохраняет код и показывает его после перезагрузки.
- **Воспроизводимость:** одинаковые seed/preset/размеры/версия дают одинаковые геометрию, названия и оформление при разных UUID новых карт; другой seed меняет результат. Отсутствующий seed возвращается в метаданных и может повторно использоваться. Пустой или чрезмерный seed, неизвестный preset и недопустимые размеры отклоняются.
- **PostGIS и атомарность:** проверить непустоту, пространственную валидность, простоту линий и границы всех вариантов; леса, озёра и реки лежат на суше, устья основных рек достигают побережья. Внутренние layerId/parentId относятся к новому экземпляру. Ошибка не оставляет частично созданной карты.
- **Права и история:** запрет чужого проекта, роли читателя и чужого Origin; обычные права редактора, выбранные день и линия. Основа не появляется в другой независимой линии, не создаётся до forkDay и сохраняет закреплённую историю веток. Изменённый вручную объект основы продолжает хранить редакции геометрии и оформления.
- **Простой интерфейс:** проверить основные подписанные инструменты, свёрнутые «Ещё», «Описание и связи», «Линия и время карты» и доступ к истории. На ширине 390 px нет горизонтального переполнения и потерянных элементов управления.
- **Регрессия:** сохранить сценарии 0.4.0 с настоящим рисованием/редактированием узлов, объединением/разделением, сохранением, конфликтами и историей, а также предыдущие семейные, календарные и каталожные сценарии.

## Проверки версии 0.4.0 — географический этап 3

Это план покрытия текущей разработки, а не отчёт о пройденном прогоне. Числа прежних выпусков ниже не относятся автоматически к 0.4.0. Итоговые команды и фактические результаты записываются отдельно после завершения.

- **Карты и слои:** создать пустую карту, проверить два начальных слоя и повторное чтение; изменить название/фон, создать и изменить пользовательский слой, его видимость, блокировку, прозрачность и порядок; удалить карту с сохранением её раннего состояния.
- **Семантическая география:** создать точку города, линию реки/дороги и территорию государства; проверить явный тип, GeoJSON, стиль, подпись и пространственное значение PostGIS. Отклонить неверный тип геометрии, пустые и самопересекающиеся полигоны, незамкнутые кольца, неконечные и выходящие за карту координаты, превышение числа вершин.
- **Целостность:** отклонить чужой слой/карту/событие/родителя, циклы территорий, присвоение существующего UUID и удаление объекта с оставшимися ссылками. Невалидная часть пакета не должна сохранить его остальные изменения. Проверить права читателя и изоляцию приватных проектов.
- **Конкурентные правки:** отправить устаревший `version` и `expectedRevision`; ожидать 409 и отсутствие частичных записей. В браузере черновик сохраняется до явного перечитывания.
- **История границ:** сохранить границы на ранний и поздний день, проверить разные геометрии и свойства; связать изменение с событием и прочитать историю объекта. Удаление и правка задним числом должны сохранять согласованность будущих ссылок.
- **Ветки:** ответвить карту на заданных дне и редакции; изменить политическую границу только в ветке, проверить неизменность родителя. Затем изменить родителя позднее и задним числом — прежняя ветка остаётся прежней. Повторить с вложенной веткой и независимой пустой линией.
- **Пространственные операции:** объединить 2–20 территорий и разделить полигон пересекающей линией; проверить реальную геометрию и площадь/части в PostGIS. Пустой результат, неподходящая линия, неправильные типы и чрезмерный набор отклоняются. До явного сохранения предварительный расчёт не создаёт редакций.
- **Редактор:** настоящими действиями на полотне нарисовать точку, линию и полигон, изменить вершину и передвинуть объект, изменить имя/цвет/подпись/событие. Проверить отмену/повтор, сохранение/перезагрузку, физическое и политическое представления, доступ к объектам через список и предупреждение при уходе с черновиком.
- **Адаптивность:** проверить доступность инструментов, форм и списка объектов на мобильной ширине; масштабирование, перемещение и полноэкранный режим не должны приводить к потере данных.
- **Миграция 006:** на отдельной базе с прежними неизменяемыми фактами применить новую миграцию и повторить мигратор. UUID, аккаунты, payload, версии и хеш исходных фактов сохраняются. У живых географических объектов тип и геометрия хранятся согласованно; прежние факты остаются без пространственных данных.
- **Регрессия:** выполнить прежние проверки сессий, приватности, карточек, календарей, зафиксированных веток, родства, групп, портретов, каталога и редактора линий; общий номер редакции карты не должен расширять прежний перенос неявными операциями.

Ручной проход: откройте «Атлас мира», создайте карту и нарисуйте материк/реку/город; переключитесь в политическое представление, добавьте государство, сохраните и перезагрузите. Выберите историческую дату, измените границу со ссылкой на событие, проверьте раннюю дату. Ответвите линию и сравните её географию с родителем после отдельной правки. На тестовых данных проверьте удаление карты, отмену и подтверждение отказа от черновика.

## Проверки версии 0.3.0

Этот раздел задаёт покрытие выпуска. Фактические результаты конкретного прогона записываются отдельным датированным отчётом после завершения всех команд. Исторические отчёты ниже сохраняются без переименования или переноса их чисел на новую версию.

- **Группы:** создать отношения с 2 и 10 участниками; отклонить 1, 11, повтор и UUID чужого мира. Изменить состав и перечитать после обновления страницы. Удаление участника группы и перенос между линиями должны учитывать всех участников; старые пары и их исторические редакции сохраняются.
- **Общая семья:** открыть и редактировать древо без выбора даты; переключить линию и убедиться, что связи остались теми же. Проверить родителя, усыновление, супругов, производных братьев/сестёр, циклы и известную биологическую хронологию. Устаревшая версия и читательские роли должны отклонять запись.
- **Переход со старой семьи:** обновить отдельную базу схемы 002 с существующими семейными связями. Совпадающие непротиворечивые источники допускают автоматическую инициализацию, различающиеся требуют явного выбора. Пустая исходная линия также является значимым расхождением. После выбора старые редакции и их UUID/данные доступны, а повторный импорт не стирает изменённую общую семью. Сравнить SHA-256 исходных неизменяемых фактов до и после миграции и повторного применения мигратора.
- **Портреты:** загрузить настоящее изображение PNG/JPEG/WebP, прочитать обработанный WebP и проверить обновление/удаление. Отклонить HTML/SVG, ложный MIME, повреждённое, анимированное, слишком большое изображение и операции без прав. После перезапуска портрет остаётся в PostgreSQL и отображается в карточке, дереве и каталоге.
- **Каталог:** проверить поиск, страницы и фильтры нескольких доступных проектов/миров/линий; подписи источника и переход к правильному варианту. Проверить один UUID в разных линиях, одноимённые разные UUID, отсутствие удалённых текущих вариантов и невозможность раскрыть чужие приватные источники.
- **Полотно линий:** через интерфейс добавить линию, передвинуть узел, создать и подписать ручное переплетение, сохранить и перечитать схему. Проверить масштаб и viewport, удаление ручной связи, запрет чужого мира и устаревшей версии. Родительские `parentRevision`/`forkDay` не меняются после этих действий.
- **Регрессия:** сохранить прежние проверки авторизации, постоянства данных, календарей, зафиксированных веток, истории, конфликтов, явного переноса и мобильных форм. Сценарии старого интерфейса семейной ветки обновляются под согласованное общее древо, а совместимость старых API проверяется отдельно.

Ручной проход нового интерфейса: создайте портрет в карточке, включите «Все персонажи» и перейдите по источнику; добавьте групповое отношение; откройте семейное древо в последнем состоянии без даты и проверьте его после смены линии; в «Редакторе линий» переместите узел, создайте переплетение, нажмите «Сохранить схему» и перезагрузите страницу. На мобильном экране основные действия должны оставаться достижимыми.

## Регрессия исторической системы этапа 2

Обязательные API- и модульные сценарии:

1. Создать редакции одной карточки на двух датах, прочитать обе и убедиться, что позднее сохранение не стирает прежний текст.
2. Ответвиться от конкретной даты и head. Править родителя после ответвления, включая задним числом; исходные данные ветки остаются прежними.
3. Внести в родителе будущую редакцию до создания ветки. Если её день позже forkDay, она не наследуется веткой.
4. Создать несколько вложенных ответвлений и независимую пустую линию. Проверить ограничение даты и редакции на каждом предке.
5. Изменить или удалить объект только в одной линии. Ранняя дата и другая линия сохраняют прежний объект. Удаление персонажа корректирует связи и участников в той же линии, сохраняя события.
6. Проверить ожидаемый version при двух параллельных сохранениях, ожидаемый head при переносе и редакцию родителя при ответвлении. Устаревший запрос получает 409 без частичной записи.
7. Проверить доступ для всех новых маршрутов, включая календари, историю, сравнение и перенос. Чужая линия и линия другого мира не дают доступ к данным или записи.
8. Сравнить линии, перенести персонажа, событие и отношение со стабильными UUID. Проверить зависимые ссылки, отказ при конфликте без подтверждения, явную замену и атомарный откат при неверном наборе.
9. Сохранить совместимость прежних исторических familyKind-отношений для пары. Проверки нового независимого древа выполняются отдельно по разделу версии 0.3.0; братья и сёстры выводятся без дополнительных записей.
10. Проверить циклы происхождения на текущей и затрагиваемой будущей исторической точке, непересекающиеся интервалы, рождение ребёнка раньше родителя и после его смерти. Не применять биологическую логику к дате усыновления.
11. Проверить григорианские 1900/2000 годы, год 0, отрицательные годы и большие ±1 000 000 000. Прямой/обратный перевод дат и пользовательские месяцы, високосные циклы и смещение эпохи должны давать согласованные целые дни.
12. Отклонить неизвестный месяц, невозможный день, дробные годы, неверный високосный цикл и некорректные большие числа. Не допускать потери точности JSON.
13. Проверить запрет `revision` в изменяющем запросе и невозможность переписать уже сохранённый payload или родословную линии через API.

Миграция проверяется на отдельной базе с данными схемы 001: сохранить UUID, значения и версии карточек, событий и отношений, применить 002 и сравнить исходное состояние. Участники событий, вход прежним аккаунтом и повторный запуск миграций должны сохраниться. История прошлых эпох из аудита не выдумывается. Перед проверкой обязательна изоляция от рабочей базы; сброс пользовательской БД недопустим.

## Ручная проверка этапа 2

1. На основной линии создайте персонажа и сохраните одну биографию на раннюю дату, другую — на позднюю. Переключение даты должно показывать соответствующий текст.

3. Откройте общее семейное древо без выбора даты и добавьте родителя и двух детей. Проверьте производное родство и сохранение семьи после переключения линии. Попытка сделать потомка собственным предком должна завершиться понятной ошибкой.
4. Создайте календарь со своими месяцами и високосным циклом. Переведите дату через общий день и выберите её как исторический срез. Проверьте отрицательный год и возврат к стандартному календарю.

6. Удалите тестового персонажа в одной линии, затем откройте раннюю дату и другую линию. Исторические состояния и связи должны сохраниться.
7. Проверьте те же действия после перезапуска приложения и на мобильной ширине экрана. Выбранные календарь и исторический срез не должны менять смысл григорианских годов событий и рождения.

Инструкции запуска 0.5.0 сохранены в черновике облачной конфигурации; сохранение черновика не публикует среду и не подтверждает восстановление в новой задаче.
