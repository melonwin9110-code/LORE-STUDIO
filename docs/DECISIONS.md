# Технические решения

Автор проекта: **ElpisHeart**.

## 001. Рабочий срез перед расширениями

Начальная реализация ограничена этапами 0 и 1 по прямому требованию пользователя. Реализуются связанные операции с постоянными данными. Карты, Wiki, ИИ и временные ветки не имитируются в интерфейсе. Переход к этапу 2 требует отдельного подтверждения.

## 002. Единое приложение Next.js

React-интерфейс и TypeScript API работают в одном Next.js-приложении. Это уменьшает объём локальной инфраструктуры и позволяет использовать same-origin cookie без отдельной настройки CORS. Серверная логика отделена от HTTP-маршрутов и клиентских компонентов.

## 003. PostgreSQL и явные SQL-миграции

Драйвер `pg` и параметризованный SQL дают явные транзакции, внешние ключи и контроль конкурентных обновлений без дополнительного ORM. Схема развивается миграциями, а не пересозданием таблиц. Docker Compose предоставляет PostgreSQL 17 с PostGIS. Географические таблицы и OpenLayers откладываются до этапа 3.

## 004. Сессии на сервере

Случайный непрозрачный токен передаётся в HttpOnly-cookie, его хеш хранится в PostgreSQL. Сессию можно отозвать при выходе; пароль никогда не хранится открытым текстом. Для хеширования используется встроенный в Node.js scrypt. В локальной HTTP-среде `Secure` отключён; при HTTPS требуется `SECURE_COOKIES=true`.

## 005. Приватные данные и проверка границ мира

Права проверяются на сервере для каждого объекта через его проект. Связь или участник события не могут ссылаться на персонажа другого мира. Текущий выпуск обеспечивает личные проекты владельцев; приглашения и расширенная совместная работа остаются следующей задачей.

## 006. Простые годы вместо преждевременной календарной системы

В первом выпуске исторические годы — целые числа в диапазоне ±1 000 000 000. Отрицательные годы допустимы, конец диапазона не предшествует началу. `JavaScript Date` используется только для служебных дат, а не как модель вымышленного времени. Пользовательские календари и преобразования вводятся на этапе 2 отдельной миграцией.

## 007. Контроль конфликтов

Персонажи, события и отношения имеют счётчик `version`. Обновление требует актуальную версию и возвращает 409 при несовпадении. Это защищает от незаметного сохранения поверх более свежей правки. Аудит хранит факт изменения; полноценная история состояний и восстановление через интерфейс не заявляются.

## 008. Демонстрация без общего пароля

«Элирия» создаётся внутри авторизованного аккаунта как приватный демонстрационный проект. Общей учётной записи с публичным паролем и автоматически открытых данных нет. Повторный запрос демонстрации не должен бесконтрольно дублировать один проект.

## 009. Зависимости только по текущей необходимости

Стек следующих этапов сохраняется в PRD. OpenLayers, React Flow, Tiptap, Yjs и Hocuspocus не нужны для выполнения текущего среза и добавляются при реализации соответствующих модулей. Внешние шрифты и обязательные платные API не требуются.

## 010. Честные результаты тестирования

Unit-тесты проверяют существенные правила. Интеграционные тесты обращаются к настоящему API и PostgreSQL, Playwright — к приложению в браузере. Пропущенные или недоступные проверки отмечаются отдельно. Команды запуска и план тестирования не выдаются за доказательство успешного прогона.
