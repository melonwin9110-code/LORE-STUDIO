# Lore Studio

Автор проекта: **ElpisHeart**.

Русскоязычное рабочее пространство для создания вымышленных вселенных. Первый выпуск охватывает этапы 0 и 1: регистрацию и вход, приватные проекты, миры, персонажей, отношения и события с простой хронологией. Данные хранятся в PostgreSQL; платные API и DeepSeek для запуска не нужны.

## Требования

- Node.js 24 LTS и npm.
- Docker с Docker Compose для локальной PostgreSQL 17 / PostGIS.
- Chromium для браузерных тестов; для разработки браузер устанавливать не требуется.

Версии JavaScript-зависимостей зафиксированы в `package-lock.json`. База данных работает в отдельном контейнере с постоянным томом.

## Запуск

Из каталога репозитория:

```sh
npm ci
test -f .env || cp .env.example .env
docker compose up -d --wait db
npm run db:migrate
npm run dev
```

Сервер разработки слушает порт 3000. При запуске на своём компьютере откройте этот порт в браузере. В облачной среде используйте предоставленный платформой способ доступа к порту: локальный адрес внутри машины не является внешней ссылкой.

`DATABASE_URL` в `.env` задаёт подключение к PostgreSQL. Значения из `.env.example` предназначены для локального контейнера. Не используйте локальный пароль `lore_local` для публичного развёртывания и не добавляйте `.env` в Git.

Для проверки производственной сборки:

```sh
npm run build
npm run start
```

Перед запуском должны быть доступны PostgreSQL и применены миграции. Сборка приложения не заменяет эти шаги.

## Первая проверка

1. Зарегистрируйте собственную учётную запись. Общего демонстрационного логина с известным паролем нет.
2. Создайте демонстрационный проект «Элирия» кнопкой в панели проектов. Он принадлежит вашей учётной записи и остаётся приватным.
3. Откройте мир, изучите персонажей, отношения и исторические события.
4. Создайте своего персонажа, сохраните карточку, измените биографию и сохраните повторно.
5. Добавьте событие с годом и участниками. Проверьте его в хронологии.
6. Перезагрузите страницу и убедитесь, что изменения сохранились.
7. Создайте второй проект и мир, проверьте редактирование и удаление объектов. Удаление проекта или мира удаляет его содержимое; используйте для этого тестовые данные.
8. Выйдите и войдите другой учётной записью. Проекты первого пользователя не должны отображаться и не должны быть доступны через API.

Редактор поддерживает статусы «Черновик» и «Канон». Годы вымышленного мира — целые числа, включая отрицательные, в диапазоне от −1 000 000 000 до 1 000 000 000. Это простая хронология, без пользовательских календарей и исторических версий карточек.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

Интеграционные и браузерные тесты используют отдельную базу `lore_studio_test`. Подготовка создаёт её при отсутствии и применяет миграции без удаления существующих данных:

```sh
npm run test:prepare
DATABASE_URL=postgresql://lore:lore_local@127.0.0.1:5432/lore_studio_test npm run dev -- --port 3001
```

В другом терминале запустите API-проверки и браузерные сценарии:

```sh
TEST_BASE_URL=http://127.0.0.1:3001 npm run test:integration
npx playwright install --with-deps chromium
DATABASE_URL=postgresql://lore:lore_local@127.0.0.1:5432/lore_studio_test npm run test:e2e
```

Playwright использует порт 3001 и при необходимости сам запускает тестовый сервер. Если в облачной машине уже установлен Chromium, загрузка браузера не нужна:

```sh
DATABASE_URL=postgresql://lore:lore_local@127.0.0.1:5432/lore_studio_test CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

Тесты создают собственные учётные записи и объекты. Не запускайте интеграционные и браузерные проверки против базы с ценными данными. Подробности и ручные сценарии — в [docs/TEST_PLAN.md](docs/TEST_PLAN.md). Фактические результаты конкретного запуска приводятся в отчёте об изменениях; наличие команды не означает, что она уже выполнена в вашей среде.

## Данные и безопасность

Каждый запрос к объектам проверяет доступ на сервере. Новые проекты приватны. Пароли хешируются с помощью scrypt; сессии используют HttpOnly-cookie, в базе хранится хеш случайного токена. Запросы изменения данных проверяют источник. Одновременное редактирование карточек контролируется полем `version`: устаревшее сохранение возвращает конфликт, вместо перезаписи новой редакции.

Для развёртывания за HTTPS установите `SECURE_COOKIES=true`, задайте `APP_URL` равным внешнему origin приложения при работе за reverse proxy, используйте собственные учётные данные PostgreSQL и настройте резервное копирование. `APP_URL` нужен, когда адрес, видимый браузеру, отличается от адреса, который получает Next.js. Автоматическое публичное развёртывание, почтовая доставка и восстановление пароля в первом выпуске не входят в функциональность.

Остановка контейнера без удаления данных:

```sh
docker compose stop db
```

Данные сохраняются в Docker volume. Команда `docker compose down -v` удаляет этот том и не нужна для обычного перезапуска.

## Границы первого выпуска

Реализуется рабочий вертикальный срез этапов 0 и 1. Приглашения участников, расширенные роли и объектные права, исторические версии, семейные древа, карты, энциклопедия, импорт/экспорт, ИИ, совместное редактирование и публикация относятся к следующим этапам. Они не выдаются за работающие функции.

До подтверждения пользователя разработка этапа 2 не начинается.
