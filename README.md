# Lore Studio

Автор проекта: **ElpisHeart**.

Русскоязычное рабочее пространство для создания вымышленных вселенных. Регистрация, приватные проекты, миры, персонажи, события и отношения хранятся в PostgreSQL. Версия 0.3.0 добавила независимое семейное древо, отношения на 2–10 персонажей, визуальный редактор линий, портреты и общий каталог. Версии 0.4.0–0.5.0 добавили атлас, исторические карты и готовую основу для ручного редактирования. Версия 0.6.0 реализует этап 4: энциклопедию с авторскими статьями, автоматическими карточками, ссылками, поиском и историческими версиями. Платные API и DeepSeek для запуска не нужны. Состояние проверок конкретного выпуска приведено в [плане тестирования](docs/TEST_PLAN.md).

## Требования

- Node.js 24 LTS и npm; зависимости зафиксированы в `package-lock.json`.
- Docker с Docker Compose для PostgreSQL 17 / PostGIS. На Windows нужен запущенный **Docker Desktop** с **Linux containers**.
- Chromium нужен для браузерных тестов; устанавливать его для обычного запуска приложения не требуется.

## Запуск на Windows в PowerShell

Откройте Docker Desktop через меню «Пуск» и дождитесь **Engine running**. Затем откройте PowerShell в распакованной папке проекта. Используйте `npm.cmd`: PowerShell может блокировать выполнение `npm.ps1`, даже если сам Node.js установлен правильно.

```powershell
npm.cmd ci
if ($LASTEXITCODE -ne 0) { throw 'Не удалось установить зависимости' }

if (!(Test-Path .env)) { Copy-Item .env.example .env }

docker compose up -d --wait db
if ($LASTEXITCODE -ne 0) { throw 'Запустите Docker Desktop и проверьте Linux containers; база ещё не готова' }

npm.cmd run db:migrate
if ($LASTEXITCODE -ne 0) { throw 'Миграции не завершены; проверьте PostgreSQL перед запуском' }

npm.cmd run dev
```

Сервер слушает порт **3000**. На своём компьютере откройте адрес `Local`, который напечатал Next.js. Окно с сервером оставьте работающим; другие команды выполняйте в новом окне PowerShell из той же папки.

Ошибка `dockerDesktopLinuxEngine ... The system cannot find the file specified` означает, что нужный движок Docker Desktop недоступен. Сначала запустите Docker Desktop и исправьте показанную им ошибку, затем повторите запуск `db`. Ошибка миграции `ECONNREFUSED 127.0.0.1:5432` после этого обычно означает, что база так и не запустилась. До успешного `docker compose up -d --wait db` выполнять миграции не нужно.

### Если Next.js завершается с паникой Turbopack

Сообщение `task ... is missing in memory or persistent storage`, `stale reference` или паника `tokio-runtime-worker` после успешных миграций указывает на аварийное завершение сборщика Turbopack. После остановки сервера браузер показывает `ERR_CONNECTION_REFUSED`; повторно создавать базу для этой ошибки не нужно.

Начиная с версии **0.2.1**, команды `dev` и `build` явно используют встроенный в Next.js **Webpack**. После обновления запускайте обычную команду `npm.cmd run dev`. В ранее скачанной версии можно сразу выбрать этот сборщик:

```powershell
npm.cmd run dev -- --webpack
```

Если после смены сборщика остаются ошибки старых сгенерированных файлов, сначала остановите Next.js сочетанием **Ctrl+C**, затем очистите только каталог сборки и запустите обновлённую версию:

```powershell
if (Test-Path .next) { Remove-Item -Recurse -Force .next }
npm.cmd run dev
```

Сохраните `.env` и том PostgreSQL: очистка `.next` не требует удаления данных или повторной регистрации. Результаты облачных проверок отдельно от воспроизведения ошибки на Windows приведены в плане тестирования.

## Запуск на Linux и macOS

Из каталога репозитория:

```sh
npm ci
test -f .env || cp .env.example .env
docker compose up -d --wait db
npm run db:migrate
npm run dev
```

Переходите к следующей команде после успешного завершения предыдущей. В облачной среде используйте предоставленный платформой способ доступа к порту; адрес внутри облачной машины не является внешней ссылкой.

`DATABASE_URL` в `.env` задаёт подключение к PostgreSQL. Значения `.env.example` предназначены для локального контейнера. Существующий `.env` сохраняйте; файл не добавляется в Git. Для размещения вне локальной машины используйте собственные учётные данные БД.

Производственная сборка:

```sh
npm run build
npm run start
```

Команды `dev` и `build` проекта используют Webpack. В PowerShell замените `npm` на `npm.cmd`. Перед запуском нужны доступная PostgreSQL и применённые миграции. Сборка приложения не заменяет миграции.

## Обновление скачанной версии с сохранением миров

1. Остановите только сервер Next.js сочетанием **Ctrl+C**. Оставьте Docker Desktop и базу работающими.
2. Сохраните существующий `.env` отдельно от распаковываемого ZIP. При необходимости сделайте резервную копию БД командами ниже.
3. Распакуйте новую версию проекта. Перенесите свой `.env` в новую папку проекта, сохранив прежний `DATABASE_URL`. Не заменяйте его шаблоном.
4. Выполните команды установки и запуска для своей системы: `npm ci`, запуск `db`, `npm run db:migrate`, затем `npm run dev`. На Windows используйте `npm.cmd`.
5. Войдите прежним аккаунтом и проверьте свои миры. Повторная регистрация для обновления не требуется.

В `compose.yaml` закреплено имя проекта `lore-studio`. При обычном запуске без другого `-p` новая папка с ZIP использует тот же постоянный том **`lore-studio_lore_data`**. Пользователи и лор находятся в этом томе, а не в `node_modules` или папке исходников. Не удаляйте том, не запускайте `docker compose down -v` и не сбрасывайте БД ради обновления.

Миграции применяются последовательно и сохраняют существующие UUID, аккаунты, данные, версии и связи. Миграция 002 переносит первый выпуск в исходные редакции основной линии. Дополнения 003–005 подготавливают независимое родство, портреты и схему редактора линий; 006 добавляет виды географических объектов и пространственный столбец редакций, 007 — Wiki-статьи и приватные изображения без перезаписи прежних фактов. Старые исторические записи семейных отношений сохраняются. Если прежние линии содержат разные семейные связи, после входа выберите исходную версию для общего древа в предложенном интерфейсом переносе. Это разовый выбор; дальнейшая смена линии не подменяет семейное древо.

Перед обновлением можно создать резервную копию из папки старой версии:

```powershell
docker compose exec -T db pg_dump -U lore -d lore_studio -Fc -f /tmp/lore-studio-before-update.dump
docker compose cp db:/tmp/lore-studio-before-update.dump ../lore-studio-before-update.dump
```

Те же команды работают в Linux/macOS. Файл записывается внутри контейнера и копируется через Compose, поэтому бинарный дамп не проходит через текстовое перенаправление PowerShell. Сохраните его вне Git и не публикуйте: в нём находятся ваши данные. Восстановление проверяйте в отдельной базе; штатная миграция не требует восстановления дампа.

## Работа с миром и историей

Зарегистрируйте собственный аккаунт и создайте проект с миром либо откройте личную демонстрационную «Элирию». Общего демонстрационного пароля нет. Проекты приватны по умолчанию.

- В режиме последнего состояния редактируются актуальные карточки. Выбор конкретной даты показывает исторические состояния объектов выбранной линии; сохранение создаёт новую редакцию с этой датой действия.
- Для ответвления выберите дату и родительскую линию. Ветка фиксирует дату и редакцию родителя. Последующие правки родителя, в том числе задним числом, не переписывают её исходные данные. Новая независимая линия начинается пустой.
- Изменения в ветке и удаления действуют только в ней. Для правки дочерней линии нельзя выбирать дату раньше её ответвления.
- Сравнение линий показывает различия общих UUID. Перенос выбранных объектов выполняется атомарно; замена отличающихся данных требует явного подтверждения. При переносе связанных объектов можно включить необходимых персонажей.
- **Семейное древо** относится ко всему миру: его можно открыть и редактировать без выбора исторической даты или временной линии. Указывайте биологического или приёмного родителя направлением **родитель → ребёнок**. Братья и сёстры выводятся из общих родителей. Циклы происхождения и известные биологические противоречия отклоняются.
- Календари задают названия и длины месяцев, високосное правило, подпись эры и смещение начала отсчёта. Даты разных календарей сопоставляются через общий целый день. Определение сохранённого календаря неизменно; для другого правила создайте новый календарь.

Внутреннее время не использует `JavaScript Date`: по API дни передаются десятичными строками, расчёт выполняется через `BigInt`. Поддерживаются отрицательные и большие годы. Служебное время регистрации и сохранения — обычное время сервера.

**Годы рождения, смерти, событий и интервалов отношений, введённые в первом выпуске, остаются григорианскими годами.** Выбор другого календаря меняет представление даты исторического среза и её перевод, но не переопределяет эти поля. Полная система приблизительных дат, диапазонов и относительных выражений ещё не реализована. Статусы «Черновик»/«Канон» объектов и признак каноничности линии — разные свойства.

## Возможности версии 0.3.0

Поведение этого выпуска описано ниже. Фактические команды, результаты и ограничения проверки приведены в [TEST_PLAN.md](docs/TEST_PLAN.md).

- **Отношения на 2–10 участников.** Одна связь описывает пару или группу разных персонажей одного мира. Состав можно изменять; существующие парные отношения сохраняются. Групповая связь не разворачивается в отдельную запись для каждой пары. Исторические редакции отношений продолжают учитывать выбранные линию и дату.
- **Семейное древо мира.** Независимые семейные связи используют общие UUID персонажей и не переключаются вместе с исторической линией. При первом обновлении одинаковые непротиворечивые семейные данные переносятся автоматически; различающиеся исходные семьи требуют явного выбора. Предыдущие исторические отношения остаются доступны в истории.
- **Редактор линий.** Полотно показывает линии и зафиксированные ответвления. Можно добавлять линии, перемещать узлы, менять масштаб, рисовать связи «пересечение», «влияние» и «переход», подписывать их и сохранять схему. Такие связи обозначают взаимодействие историй. Родитель и дата уже созданного ответвления остаются зафиксированными; содержимое между линиями переносится явной командой сравнения и переноса.
- **Портреты персонажей.** Загрузите PNG, JPEG или WebP размером до 5 МиБ в карточке сохранённого персонажа. Сервер проверяет и обрабатывает изображение; портрет можно заменить или удалить. Он общий для стабильного UUID персонажа в разных линиях и виден в карточках, древе и каталоге. Файл хранится в PostgreSQL вместе с мирами, поэтому обновление ZIP и резервная копия БД сохраняют изображение.
- **«Все персонажи».** Отдельный режим показывает доступные вам карточки разных проектов, миров и линий. Подпись **проект → мир → линия** объясняет контекст каждой строки и позволяет перейти к персонажу. Варианты одного UUID в разных линиях видны с соответствующей подписью; приватные данные других пользователей не включаются. Доступны поиск, фильтры и постраничная загрузка.

## Карты — версия 0.5.0

Географический этап следует первоначальному ТЗ и сохраняет возможности предыдущих выпусков. Подтверждённые результаты и границы проверки приведены в [TEST_PLAN.md](docs/TEST_PLAN.md).

В разделе **«Атлас мира»** нажмите «Новая карта» или «Создать первую карту» и выберите начало:

- **Готовая основа** — один большой остров, несколько материков или архипелаг. Создаются береговые контуры, рельеф и леса, реки и озёра, поселения и дороги, государства и провинции. Это обычные редактируемые объекты на пяти слоях.
- **Пустая карта** — чистое полотно с двумя начальными слоями для рисования вручную; этот вариант выбран по умолчанию.

Укажите название и размеры. В готовой основе необязательный **«Код мира»** задаёт вариант генерации; пустое поле создаёт новый код. Он сохраняется и показывается над картой после перезагрузки. Один код при одинаковых типе основы, размерах и версии алгоритма воспроизводит исходную географию; новые карты получают отдельные UUID. Основа создаётся новой картой, прежние карты и миры сохраняются.

Карта использует локальную плоскость вымышленного мира, поэтому её можно рисовать без подключения внешних тайлов. Физические и политические слои принадлежат одной карте: политическое представление добавляет границы к общей физической основе.

Выберите рабочий слой и тип объекта — например, реку, лес, государство или город — и нажмите «Нарисовать объект». Полотно поддерживает точки, линии, многоугольники, перемещение и редактирование узлов. Объединение и разделение территорий находятся в меню **«Ещё»**. Инспектор появляется при выделении объекта; дополнительные тип, описание, событие и территория-родитель открываются в **«Описание и связи»**.

Заливка, контур, толщина и подпись **сразу видны на выделенном объекте** и входят в черновик без дополнительного применения. Пунктирная рамка выделения не заменяет его оформление. У линии нет внутренней заливки: её видимый цвет задаёт поле контура/цвета линии. Название и описание применяются при выходе из поля или кнопкой «Применить свойства».

У слоя есть быстрые глазок, замок, стрелки порядка и ползунок непрозрачности. Глазок отражает видимость в выбранном представлении: политический слой скрыт в физическом режиме, а его включение переключает на политический. Замок запрещает редактировать объекты слоя; скрытые слои также недоступны для правок. Кнопка «Сохранить карту» записывает настройки слоёв вместе с объектами.

Геометрические правки образуют **черновик**: отмена и повтор меняют его до явного сохранения. Нажмите «Сохранить карту», чтобы записать слои и объекты одной транзакцией. При конфликте черновик остаётся на экране; перечитывание с подтверждением заменяет его актуальными сохранёнными данными. Смена карты, мира или исторического контекста с несохранёнными правками требует подтверждения.

Свёрнутая панель **«Линия и время карты»** над атласом выбирает дату и временную линию карты; название выбранной линии видно в её заголовке. Сохранённая граница относится к выбранному историческому состоянию; ранняя дата показывает прежнюю геометрию. Ответвление фиксирует данные родителя, поэтому его позднейшие правки не заменяют географию уже созданной ветки. Семейное древо мира остаётся независимым от этого контекста.

Новая личная демонстрационная «Элирия» содержит редактируемую карту **«Земли Элирии»**: материк, остров, лес, горы, реку, озеро, королевство и провинцию, город, порт, крепость, дорогу и подпись моря. Связи с событиями и принадлежность провинции сохраняются как настоящие данные. Ранее созданные демопроекты сохраняются без изменений; в них можно создать свою первую карту через «Атлас мира».

Карта и геометрия хранятся в PostgreSQL/PostGIS и включаются в обычный дамп базы. Обновление ZIP сохраняет их при прежнем `.env` и томе `lore-studio_lore_data`. Размеры существующей карты не меняются, чтобы случайно не обрезать уже созданные объекты. Для версии 0.5.0 новая SQL-миграция не требуется: сведения о готовой основе записываются в существующую JSONB-редакцию карты. Импорт изображений-подложек, переносимые архивы карт, развитое моделирование рельефа/климата и 3D-глобус относятся к последующим модулям.

## Энциклопедия — версия 0.6.0

Откройте **«Энциклопедия»** в выбранном мире. Слева находятся поиск и список материалов; карточки персонажей, событий, карт и географических объектов появляются из доступных данных мира. Они показывают структурированные сведения в выбранных временной линии и дате, без создания копии статьи для каждого объекта.

Создайте самостоятельную статью либо начните статью об объекте. Связанная карточка фактов и написанный вами текст хранятся отдельно: изменение биографии, имени или границы обновляет автоматические сведения, сохраняя авторскую статью. Статьи имеют название, краткое описание, категорию и теги. Метки **факт, легенда, слух, гипотеза и тайна** помогают описать характер материала. «Тайна» — метка содержания, она не скрывает статью от других участников этого приватного проекта.

Визуальный редактор Tiptap поддерживает заголовки, выделение текста, списки, цитаты, код, таблицы и изображения. Внутренние ссылки ведут к материалам того же мира; встроенные карточки персонажей и карты показывают связанный объект. Оглавление строится по заголовкам. Обратные ссылки и связанные материалы помогают переходить между страницами; поиск включает текст статей и доступных автоматических карточек. Категории, теги и тип материала служат фильтрами.

Изображение PNG/JPEG/WebP размером до **5 МиБ** загружается прямо из редактора. Сервер проверяет содержимое, убирает метаданные и сохраняет статический WebP в PostgreSQL. Файл остаётся доступен историческим версиям статьи; обычный дамп БД включает его вместе с лором. Публичное хранилище и внешние ссылки для изображений не нужны.

Изменения статьи сначала остаются в черновике. Сохраните статью явно или отмените правки. Переход к другому материалу, миру либо историческому контексту с несохранённым текстом требует подтверждения. При конфликте версии текст остаётся в редакторе для сравнения и повторного сохранения после перечитывания. Участники с доступом для чтения могут читать, искать и открывать историю, но не редактировать статьи или загружать файлы.

Статья использует ту же историческую модель, что и лор: UUID остаётся прежним, правка создаёт новую редакцию, удаление действует в выбранной линии и дате. Ветка закрепляет родительское состояние; последующие правки родителя не подменяют её статьи. История редакций позволяет прочитать прежний текст. Исчезнувшая цель ссылки обозначается как недоступная, без раскрытия чужих данных.

Перед первым запуском 0.6.0 примените **миграцию 007** обычной командой `npm.cmd run db:migrate` в PowerShell. Существующий `.env`, аккаунт и том `lore-studio_lore_data` сохраняются. Запуск по-прежнему использует Webpack.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

В PowerShell используйте `npm.cmd`. Интеграционные и браузерные тесты работают только с отдельной базой `lore_studio_test`. Её подготовка не удаляет существующие данные:

```sh
npm run test:prepare
DATABASE_URL=postgresql://lore:lore_local@127.0.0.1:5432/lore_studio_test npm run dev -- --port 3001
```

В другом терминале:

```sh
TEST_BASE_URL=http://127.0.0.1:3001 npm run test:integration
npx playwright install --with-deps chromium
DATABASE_URL=postgresql://lore:lore_local@127.0.0.1:5432/lore_studio_test npm run test:e2e
```

Переменные перед командой выше — синтаксис Linux/macOS. Эквивалент запуска тестового сервера в PowerShell:

```powershell
$env:DATABASE_URL = 'postgresql://lore:lore_local@127.0.0.1:5432/lore_studio_test'
npm.cmd run dev -- --port 3001
```

В другом окне PowerShell задайте и `$env:DATABASE_URL = 'postgresql://lore:lore_local@127.0.0.1:5432/lore_studio_test'`, и `$env:TEST_BASE_URL = 'http://127.0.0.1:3001'`, затем выполняйте `npm.cmd run test:integration` или `npm.cmd run test:e2e`. Браузер ставится командой `npx.cmd playwright install chromium`. После тестирования закройте тестовые терминалы или удалите заданную переменную командой `Remove-Item Env:DATABASE_URL`, прежде чем запускать обычное приложение в том же окне.

Playwright переиспользует указанный тестовый сервер либо запускает свой на порту 3001. Для системного Chromium в облачной машине можно задать `CHROMIUM_PATH=/usr/bin/chromium`; загрузка браузера тогда не нужна. Не запускайте два dev-сервера одного checkout одновременно и не используйте рабочую базу для автотестов. Подробные сценарии и фактические результаты — в [docs/TEST_PLAN.md](docs/TEST_PLAN.md).

## Данные и безопасность

Каждая операция проверяет сессию, роль и принадлежность объекта проекту на сервере. Пароли хешируются scrypt; HttpOnly-cookie содержит случайный сессионный токен, его хеш хранится в БД. Изменяющие запросы проверяют Origin. Устаревший `version` возвращает конфликт 409. Номер редакции линии дополнительно защищает ответвления и переносы от устаревшего состояния.

Для HTTPS-развёртывания установите `SECURE_COOKIES=true`, задайте внешний `APP_URL` за reverse proxy, используйте собственные учётные данные PostgreSQL и резервное копирование. Автоматическое публичное развёртывание, почтовая доставка и восстановление пароля не входят в этот выпуск.

Остановка БД с сохранением данных: `docker compose stop db`. Постоянный том не заменяет резервную копию.

## Границы этапа

Текущая версия 0.6.0 реализует согласованный этап 4 — энциклопедию — и сохраняет возможности карт, исторической системы и предыдущих выпусков. Переносимые архивы относятся к этапу 5; развитая генерация мира, ИИ, полноценное совместное редактирование, слияние линий и публичный Lore Portal — к следующим этапам. Приглашения, расширенные объектные разрешения, автоматическое престолонаследие и управление династиями пока не заявляются как готовые функции.
