# Правила работы над Lore Studio

Автор проекта: **ElpisHeart**. Сохраняйте авторство в интерфейсе, метаданных и README.

## Область текущей задачи

Текущий выпуск ограничен этапами 0 и 1 из `docs/PRD.md`: авторизация, приватные проекты, миры, персонажи, события, простая хронология и базовые отношения. Не переходите к этапу 2 без явного подтверждения пользователя после проверки первого выпуска.

Задачи в облачной среде уже изолированы. Используйте существующий checkout; не создавайте Git worktree без явного запроса пользователя. Не удаляйте пользовательские файлы, данные и изменения. Не выполняйте сброс базы ради устранения ошибки.

## Архитектура и данные

- Поддерживайте Next.js App Router, TypeScript и PostgreSQL как единственный источник постоянных данных. Не заменяйте серверное хранение localStorage.
- Сохраняйте стабильные UUID объектов и связи внутри одного мира. Проверяйте принадлежность связанных объектов на сервере.
- Проверяйте авторизацию и права на каждой операции с проектами и объектами. По умолчанию проекты приватны; не делайте их публичными без явного действия автора.
- Валидируйте входящие данные и используйте параметризованные SQL-запросы.
- Не переносите секреты, `DATABASE_URL` или серверные зависимости в клиентский код. Не печатайте значения секретов в логи.
- Обновляйте схему миграциями; сохраняйте повторяемость миграций и существующие данные.
- Не путайте служебные даты создания записей с временем вымышленного мира. Исторические годы в текущем срезе — целые числа, а не `JavaScript Date`.
- Сохраняйте контроль `version` при редактировании. Ошибка конфликта должна оставлять пользователю возможность перечитать актуальные данные.
- История аудита первого этапа не заменяет исторические версии и неизменяемые снимки веток следующего этапа.

## Интерфейс

Русский язык по умолчанию, доступные подписи форм, адаптивная вёрстка и единый стиль. Нереализованные разделы скрывайте или явно помечайте как запланированные. Не добавляйте фиктивные ИИ-ответы, графики и показатели, выдаваемые за данные пользователя.

Приложение должно запускаться без платных сервисов. При появлении ИИ он остаётся отдельным необязательным модулем, а изменения канона требуют подтверждения пользователя.

## Проверка изменений

Запускайте проверки, соответствующие изменениям: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, интеграционные и E2E-тесты при изменении поведения приложения. Тесты должны проверять действительное сохранение, разрешения и ошибки, а не повторять реализацию.

Не описывайте непройденную или незапущенную проверку как успешную. Указывайте конкретный блокер, если проверка недоступна. Используйте отдельную тестовую базу; не удаляйте рабочие проекты для подготовки тестов.

При существенных изменениях обновляйте README и соответствующие документы в `docs/`. Новые зависимости добавляйте только по необходимости и фиксируйте lockfile. В отчёте укажите реализованное поведение, проверки, ограничения и команду запуска.
